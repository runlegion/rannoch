# Changelog

## 0.2.0

Minor release: the public signatures change, which while rannoch is 0.x makes this a minor release. Property values are typed (`Value` replaces `String` in `Node`, `NodeFact`, `Description` and `Unit::new`), `Class::properties` maps each property to its `ValueType`, `Declaration::Property` carries its type, `Node` and `NodeFact` gain `derived_from`, and `Graph::compact` is removed in favour of `Graph::snapshot`. A store written by 0.1.1 opens whole with no migration step: rannoch's new tables (`_derived`, `_followers`) are created on open, its properties read as text and its classes keep recording order.

This is the first part of the 0.2 redesign (FR-RANNOCH-055, 056, 057, 058, 061, 062, 063, 064, 075, 079, 080 and 081). An app can now write through an in-memory queue that a heartbeat commits as one transaction with a savepoint per write; `Graph::write` still commits directly. A write that breaks its class's declaration is refused when it is written, and one that fails at commit is reported with every write that depended on it. The store keeps every event: a snapshot replaces compaction. Followers read events since a stored cursor, bounded and filtered, from this process or another, and the graph reports the mark every registered follower has read. A fact can name the events it was derived from. A new workspace crate, `rannoch-probe`, measures the memory a host allows and how fast a directory takes durable writes. The tag is still the release: pin `rannoch = { git = "https://github.com/runlegion/rannoch", tag = "v0.2.0" }`.

### Added

- **Declared value types and a class's history key** (PR #56, #47, FR-RANNOCH-055): a class declares each property's `ValueType` (`Text`, `Integer`, `Decimal`, `Float` or `FloatVector(n)`) and its `HistoryKey`: `Integer` or `Time` supplied by the writer, or `Recorded`, the default. Values sit in typed columns and read back as `Value` of their declared type. An integer such as 9007199254740993 stays exact, and a decimal is held as text and keeps every digit. `Ontology` names each class's history key. A store written by 0.1.1 (kept as `tests/fixtures/store-0.1.1.rannoch`) opens with every event, its properties as text and its classes in recording order.
- **A write that breaks its class's declaration is refused at once** (PR #57, #48, FR-RANNOCH-056): the property checks moved from each piece into the whole-write check. A wrongly typed value is refused before any piece commits, and a node missing a property its class declares is now refused too.
- **The heartbeat write queue** (PR #65, #49, FR-RANNOCH-057): `Queue::open(graph, interval)` takes a `Graph` and commits on a heartbeat (`Queue::INTERVAL` is 20 ms). `Queue::write` checks the write against the in-memory ontology, refuses at once what it refuses, and otherwise returns a `Ticket` before the write is committed. A heartbeat commits everything queued, advances the committed watermark (`Queue::committed`) and only then fires the `Queue::subscribe` subscribers, so a subscriber never hears of an event that is not committed. `Queue::flush` commits now and returns when every write accepted before it is committed.
- **A heartbeat's batch is one transaction with a savepoint per write** (PR #70, #62, FR-RANNOCH-058): each write in the batch runs unsplit under its own savepoint, so one failing write rolls back alone and the rest commit. A batch of more than 1,000 changes lands whole for a reader, never in part. A link from a node that a failed write would have brought new fails with it, while a link from a node already in the graph keeps its source. If the file rolls back the whole transaction, every ticket in the batch fails rather than continuing in a second transaction.
- **Dropping or closing the queue commits what it holds** (PR #69, #61, FR-RANNOCH-061): dropping a `Queue` stops the heartbeat and commits what is still queued, so a process that returns or panics with unwinding loses no write. `Queue::close` does the same explicitly for a process about to exit without unwinding.
- **A write that fails at commit is reported, never dropped in silence** (PR #77, #63, FR-RANNOCH-075): every queue failure travels one channel, the public `Failure` (`Write`, `Heartbeat`, `Subscriber` or `Unfired`). Each is reported once, to whichever takes it first: `flush` and `close` return it, `take_failures` collects it, or the `on_failure` handler receives it when the queue drops. A failed write comes back with every write that depended on it, such as a link from a failed node. A subscriber that panics does not stop the heartbeat. If the heartbeat itself panics mid-batch, the batch goes back to the front of the queue in order and the next flush, close or drop commits it or reports each write.
- **Snapshots replace compaction; the store keeps every event** (PR #60, #50, FR-RANNOCH-062): `Graph::snapshot(cursor, path)` writes the graph's state and ontology at a cursor into a file of its own. It reads the log, deletes nothing and never takes the graph's write lock. `Snapshot::rebuild(later, path)` starts a graph from the snapshot plus the events after its cursor, keeping declarations, the history key, declared types and each node's fate (forgotten or replaced). A new reader starts at `events().since(snapshot.cursor())`. The forgotten-fate defect carried in 0.1.1's known issues (#30) no longer applies, because nothing erases events.
- **Events since a stored cursor, bounded and filtered** (PR #68, #51, FR-RANNOCH-063): `Events::since_until(cursor, until, keep)` returns the events after a cursor up to an inclusive bound, keeping only the changes `keep` accepts. `Cursor` serializes as its number so an app can store it. A rebuild, from the start or from a snapshot, replays each event under its own place in the log, so a stored cursor names the same event afterwards and a follower behind a snapshot still catches up.
- **The committed watermark is readable across processes** (PR #74, #52, FR-RANNOCH-064): `Events::committed` returns the cursor of the last committed event. Another process on the same file follows commits by reading it and taking `since_until` its own cursor up to it, so it sees each committed event once and nothing uncommitted.
- **Registered followers and the processed mark** (PR #76, #58, FR-RANNOCH-079): `Events::register`, `advance`, `unregister` and `followers` keep named follower cursors in `_followers`, and `Events::processed` reports the lowest of them, the point every registered follower has read. A new follower holds the mark at the start until it stores a cursor, and unregistering releases it. Advancing past the committed watermark is refused, so the mark never covers an event that has not arrived. A snapshot carries registrations, and `Snapshot::rebuild` lowers any carried cursor past the rebuilt graph's watermark to it. The mark deletes nothing.
- **A fact names the events it was derived from** (PR #75, #59, FR-RANNOCH-080): `Write::derived_from(events)` names the events a write's nodes were derived from, and each node reads back with `derived_from` naming them. `Graph::derived(event)` answers the nodes derived from an event. A source event the graph does not hold is refused at once. Sources survive a snapshot rebuild, an identical rewrite naming new sources records them, and forgetting a node removes its derived-from rows.
- **`rannoch-probe`** (PR #66, #64, FR-RANNOCH-081): the repository is now a Cargo workspace with a second crate. `rannoch_probe::memory(cap)` reports a host's total memory and the memory it allows, the least of the total, the limit set by the process's cgroup or any ancestor cgroup, and the caller's cap. `rannoch_probe::disk(directory, budget)` measures a directory's durable write rate (`File::sync_all`, `F_FULLFSYNC` on macOS) and the time of one flush within a time budget. When it overruns, `Error::Budget` carries the flush in progress and the overrun. A measurement records the OS and when it was taken, and the probe stores nothing. CI runs its tests on Linux, macOS and Windows, and on Linux once more under a 512 MiB systemd scope.

### Fixed

- **Typed values: non-finite floats, grouped counts and later declarations** (PR #67, #55): a write carrying NaN or an infinity in a float or float-vector property is now refused when it is written, so every accepted event reads back and replays. A count grouped by a non-text property reads the group from its stored value instead of failing. A property declaration carries its value type (text when an older event names none), and redeclaring a property with another type is refused. A rebuild or snapshot replaying a node with a property its class does not declare fails, naming the event, instead of dropping the property.
- **`find_as_of` refuses rather than answers wrong** (PR #79, #71): `find_as_of` reads only a node's current version, so when that version was valid after the asked date it answered `None`, even if an earlier version held then. It now returns `Error::Refused` ("past versions are not readable yet") when the current version is valid after the date or has an unknown valid time and the node had an earlier version. A node with only one version answers as before, and the function's documentation states what it can and cannot answer.

### Changed

- **Compaction is removed** (PR #60, #50): `Graph::compact`, which deleted events, is gone along with FR-RANNOCH-043. Use `Graph::snapshot` and `Snapshot::rebuild`.
- **CI runs on merge groups and across the workspace** (PR #54, #53; PR #66, #64): the merge queue tests what it merges, and fmt, clippy, tests and doc tests cover every workspace crate, as does release preflight.

### Known issues

- **`find` returns the last-arrived version** (#72): `Graph::find` returns the version of a node that arrived last, not the newest on its class's declared history key. A write for an earlier point that arrives after a later one overwrites the current state, so two graphs holding the same events in different arrival orders can disagree on what is current. Finding the newest version on the declared axis ships in 0.2.1. Until then, a class with no declared history key behaves as documented (recording order).
- **A rebuilt graph's watermark can sit below its snapshot's cursor** (#78): after `Snapshot::rebuild` with few or no later events, `Events::committed` can report less than the snapshot's cursor, so `advance` refuses cursors the rebuilt graph already holds and carried followers re-read events. Nothing is lost. The fix ships in 0.2.1 with the history work.

## 0.1.1 (2026-10-18)

Patch release: the first tagged release of rannoch, numbered 0.1.1 so that 0.2 stays the name of the planned redesign (the 0.2 spec, FR-RANNOCH-056/062/071); nothing depended on rannoch before this tag, so the changed `walk` signature (#35) breaks no released consumer.

rannoch is one graph for the Rust projects in this ecosystem. Every change to a graph is an event. The SQLite tables are state built from those events. The graph presents itself as an ontology, so no read or refusal names a table or column. An app opens a graph file, declares its classes, relations and properties on the graph's own event stream, writes whole units, and reads by find, capped walk, exact count or describe. It can also follow its events from a cursor, compact them, forget or replace nodes, resolve references into other graph files, and rebuild a file from its events alone. Releases are git tags: the crate keeps `publish = false` and is not on crates.io, so consumers pin the tag, as in `rannoch = { git = "https://github.com/runlegion/rannoch", tag = "v0.1.1" }`.

### Added

- **The core: open, declare, write, events, find, walk and count** (PR #15, #2, #3): `rannoch::open` presents a graph file and the ontology its own stream declared. `Graph::declare` writes one event per class, relation or property and builds its table in the same transaction. An identical declaration does nothing, and a conflicting one is refused in ontology terms. `Graph::write` commits a whole `Write` in pieces of 1,000 changes. Each piece is one transaction, and its events land only if the piece lands. If a piece fails, `WriteError` returns the events of the pieces that landed before it. A link to a key that is not present yet waits as an open link and closes with one event when the key arrives. Reads are `events().since(cursor)`, `find`, `find_as_of`, `find_link`, `walk` (capped, in either direction with `<-`) and `count` (distinct, total and grouped tallies over many roots in one query, with an optional relation filter). Storage is bundled SQLite with one table per class and one per relation.
- **A link holds only between its relation's declared classes** (PR #18, #4): `Graph::write` checks the whole write before any piece commits. If a link's source key is a node of a class other than the relation's declared source class, the write is refused with `Error::Refused`, nothing lands and no event is written.
- **Forgetting** (PR #19, #5): `Graph::forget(target, rule, source)` removes a node and every link touching it from live state in one transaction. It rewrites each earlier `Wrote` event that carried the node so the node keeps its class and key but loses its properties, and appends a `Change::Forgot` event naming what left.
- **Compaction** (PR #20, #6): `Graph::compact(cursor)` deletes the log's events up to a cursor the app chooses. Graph state lives in the tables, so counts are unchanged, and event sequence numbers are never reused, so `since(cursor)` still returns every later write for an app to fold onto its compacted base.
- **Open-links read** (PR #17, #7): `Graph::open_links` lists every link still waiting for its other end, with both ends and the kind and key it waits on. If a write adds a node of the wrong kind under a waited-on key, the link stays open and the piece's `Wrote` event reports a `WrongKind`.
- **Describe a node** (PR #22, #8): `Graph::describe(&NodeRef)` returns a `Description` with the node's class, key and properties, its relations by name in both directions with counts, and its containment ancestors (`PartOf`), nearest first.
- **Replacing a node** (PR #23, #9): `Graph::replace(class, old, new)` records the old node's fate and appends one `Change::Replaced { class, old, new }` event in a single transaction. After that, `describe` on the old node answers `replaced_by`.
- **References into another graph file** (PR #24, #10): `Graph::mount(name, path)` opens another graph file under a name. `Graph::resolve(mount, &NodeRef)` answers the target's `Fate` (`Live`, `Forgotten { rule }` or `Replaced { by }`) from that file's own facts only, and writes nothing to the referring file.
- **As-of reads over valid time** (PR #16, #11): `Graph::walk_as_of` and `Count`'s `as_of` read only nodes and links valid on or before a date, checking every link and node along the path. A stated-unknown valid time is never read as now. A read without `as_of` returns unknowns marked `ValidTime::Unknown`.
- **Rebuild from events** (PR #21, #12): `rannoch::rebuild(events, empty_path)` replays a graph's events in log order into an empty file in one transaction, keeping each event's original id. The ontology, nodes, links and open links all come back, and closed links come back with the source they were opened with.
- **Measurement harness** (PR #25, PR #41, #13, #40): `tests/measure.rs` holds `#[ignore]` tests that run NFR-RANNOCH-011, 012, 013, 014 and 016 as written. Each prints the measured value, the target and whether it met the target. They run by hand at verify time, never from a daemon. Since PR #41 they run on Linux (`VmHWM`), macOS (`ru_maxrss`) and Windows (an in-process working-set sample every millisecond) and find legion's store in the platform data directory or `LEGION_DATA_DIR`. A new CI job lints all targets on ubuntu, macOS and Windows in parallel.
- **Release tooling** (PR #43, #42): `release.toml`, `scripts/release.sh`, `scripts/sync-version.sh`, `scripts/test-release.sh`, `RELEASING.md` and a `release.yml` workflow. On a `v*` tag, the workflow checks the tag against `Cargo.toml`, builds, and creates the GitHub release with the matching CHANGELOG section as its notes. It has no crates.io step.

### Fixed

- **A walk from an undeclared class is refused in ontology terms** (PR #26, #8): such a walk used to return the storage error `no such table: class:ghost`. It now refuses with `class ghost is not declared`.
- **A forget takes the node's open links with it** (PR #27, #5): forgetting a node used to leave its open links in live state, so `open_links()` still listed the forgotten key and writing the key again closed the leftover link onto it. Those open links are now removed and named in the `Forgot` event, and a rebuild does the same.
- **A walk asked for every hop ends** (PR #28, #2): a walk with `hops = usize::MAX` never returned once it ran out of nodes before its cap. It now stops as soon as there is nothing left to walk from.
- **Out-of-range dates are refused, and valid times compare by value** (PR #36, #34): writes and as-of reads used to accept dates such as month 13, February 29 in a common year or April 31. Every as-of comparison also compared dates as text, so a node valid `2020-01-01` was not found as of `2020-01`. Writes now check every valid date before any piece commits. `find_as_of`, `walk_as_of` and `count` refuse a bad `as_of`, and all three compare dates as (year, month, day), with a month standing for its first day. Stored valid times are not rewritten, and a file holding an old out-of-range date still rebuilds.
- **Replace refuses equal keys and keys that are not nodes** (PR #37, #33): `replace("item", "x", "x")` used to succeed and leave `x` replaced by itself, and replacing between two absent keys also succeeded. Equal keys now return `Error::Refused`, and a missing old or new node returns `Error::NotFound`. In both cases no event is written and no fate changes.
- **A handle's reads use the ontology the file holds now** (PR #38, #32): a handle used to keep the ontology it loaded at `open`, so it refused, and graphs that had mounted the file refused, a class or property another handle declared later. Reads now check the file's schema version and reload the ontology only when it has changed, so a plain data write costs a read one pragma and no reload.

### Changed

- **`walk` and `walk_as_of` return a `Walk`** (PR #39, #35): both now return `Walk { nodes, capped }` instead of `Vec<(NodeRef, ValidTime)>`. `nodes` holds at most `cap` nodes, nearest first. `capped` is true when at least one more node within `hops` (and valid as of the date, for `walk_as_of`) would have come back under a larger cap. Callers no longer need to ask for `cap + 1` to tell whether they hit the cap. This is a breaking change for any caller built against earlier `main`, which now reads `.nodes`.

### Known issues

- Three defects found before this release are not fixed in it and were closed as to be replaced by rannoch's next design: a write refused for an undeclared class or unknown property can land its earlier pieces (#29), compaction erases forgotten fates so `resolve` answers `NotFound` (#30), and `forget` scans every event, so its cost grows with the log (#31).
