# Changelog

## 0.6.0

Minor release: public signatures changed since v0.5.0, which while rannoch is 0.x makes this a minor release. `state_at`, `link_state_at` and `find_as_of` take a `&View`, `At` and `HistoryKey` are gone, a class or relation declares an `axis`, and `Version`, `Hearing` and `End::Ended` carry `axis` and `known` in place of `point`, `integer` and `at`. An amendment's data is now `{"target": {"source", "id"}, "patch": {...}}`. There is no migration from a store written by v0.5.0: its history tables lack the new columns, so `open` returns an error on it, and an app moves by writing a new store. A v0.5.0 log's amendments, and the `time`, `integer` and `at` fields of its events, are not in the form this release reads. The tag is still the release: pin `rannoch-store = { git = "https://github.com/runlegion/rannoch", tag = "v0.6.0" }`, and `rannoch-queue` and the new `rannoch-relay` at the same tag.

Every fact now has three times, each with one job: known-at from the clock in its CloudEvent id, a point on an axis its class or relation declares, and an optional valid time. An app can read a node's links, a class's nodes and whole-store counts at any view with no known key, and can keep a declared neighbourhood warm in memory with `rannoch-relay`. A worker's closes no longer cost a durable write each, and a clean fill of 306,000 events runs at about 90,000 events a second. The release check ran on main 63681e5, and main has changed only `docs/store.md` since (#187; `toys/live/RESULTS.md` on the `chore/187-release-check` branch). Producing 300,000 events through 1,630 kills left none lost, doubled or unfilled. An amendment run of 2,000 books through 166 kills gave 0 mismatches, a worker run of 30,000 events through 105 kills ended with every event done, and a real import of 22,619 events matched its source. The worker file, harness and processor crates are still empty scaffolds.

### Added

- **Three times, and a declared axis** (PR #177, #171): a hearing stores `known`, the millisecond of its CloudEvent id, apart from its `axis` point. The store's own receipt stamp still names the log id and `recorded`, but no read orders or filters by it. `Class::axis` and `Relation::axis` are ordered lists of integer part names, empty by default, and empty means the axis is known-at. An event carries its point as `data.axis`, and a missing part or a part not declared is refused. Links and endings go through the same path as nodes, so a link heard at builds 12 and 13 is two hearings, and an ending at build 14 reads as ended in a view of 14 and not of 13. A read takes `View { axis, known }`, each part optional, and a point with fewer parts than the axis reads the top of its prefix. A correction at the same point reads as the original when known before it and as the correction from its known-at on, and a link's latest conclusion is chosen by known-at and then event id, never by arrival. Known-at trusts the clock of the host that minted the event. Wider rows cost a node-only fill about 6% when measured at this PR.
- **Reads at a view with no known key, and reads as events** (PR #179, #175): `Graph::links(node, relation, Direction, view)` lists the links that hold, out or in, in the other end's key order. `nodes(class, filter, view)` lists a class's nodes in key order, and `Class::indexed` names the properties a filter may use, each with its own index, so a write pays for an index only where one is declared. `counts(view)` gives nodes per class and holding links per relation with one statement for each, never a walk. `describe(node, view)` gives the node's version and how many links hold for each relation and direction. A `rannoch.query` event can ask any of them, and `Graph::answer` returns the `rannoch.answer` body, whose subject is the query's id and whose data holds the result and the known-at it was read at. Results carry no store-local field, so the same view and log answer the same after a rebuild and in any arrival order, and a version whose valid time is unknown is returned marked unknown.
- **`rannoch-relay`, a named neighbourhood kept warm in memory** (PR #194, #151): `Declaration::Shape` names roots (one node, or a class with a filter on indexed properties) and steps. A step's relation carries its direction in its name (`r`, `r<-` or `r<->`), with optional `keep` and `drop` property maps and a `cap`. A `rannoch.query` with `{shape, view}` is answered by a `rannoch.answer` holding the relay's id, cursor and per-step counts, not the nodes, and `Graph::answer` still refuses such a query. `Relays::read` answers from memory and never touches the graph. Each relay is the worker `rannoch.relay.<id>`, and folds what a commit brought into at most one `rannoch.relay.changed` event, given to `Relays::subscribe` subscribers and not logged, with each property's before and after and the nodes that entered or left. A relay's file only saves time: a file missing or behind is reseeded from the graph. Relays of one shape and view are shared, and `release` drops one when its last holder goes. `Relays::report` logs a `rannoch.report` event naming the shape, view and cursor, and `reread` replays the log to that cursor through fill to rebuild the frozen answer. `Queue::join` starts a worker at the watermark, and `Queue::commit` commits what is held now. On a 902-node relay built from real data on the `toys/relay` branch, a seed took 44-46 ms, `read` had a p50 of 41 ns, and a round trip through the inbox had a median of 27.2-28.3 ms and a p99 of 68-84 ms.

### Fixed

- **A link found wrong no longer holds** (PR #191, #190): `link_state_at`, `links`, `counts` and `describe` all kept returning a link after a `rannoch.corrected` event, and a link heard, ended and then corrected came back as holding. From a correction's known-at on, across the whole axis, a link now does not hold until a live hearing whose event sorts after the correction follows it. An amendment or rename does not reopen it. `link_state_at` returns such a link with `ended: true`, which now means the link does not hold, and `link_end` returns `Corrected` until it reopens. A private `_corrections` table keeps every correction, so one stays in force after a later conclusion replaces it as the latest.
- **An ended link under a renamed key is known only from the rename** (PR #196, PR #197, #187): a rename copied a link's endings onto the new key with their own known-at, so a read as known before the rename found the ended link under the new key, where the docs say it answers under the old key alone. In the amendment kill run this was 100 mismatches of 2,000 books. An ending kept under a key reached by a rename is now known there from the rename at the earliest, in either arrival order. Under the new key, `link_end` and `Version.known` therefore give a copied ending the rename's known-at, and the ending keeps its own under the old key.
- **A closed-link event is handed out by the commit that filled it** (PR #176, #172): fill logs `rannoch.closed.<relation>` after the batch that moved the watermark, so on an idle store those events sat past the watermark until a later commit. The queue now moves the watermark to the log's committed high after fill, so `next` reaches them as soon as `flush` returns.
- **Alias lookups seek instead of scanning the line** (PR #181, #180): the alias side of every occurrence query read every alias in the line, once per fact fill touched and once per read. A 300,000-event fill that re-sent 15,000 links ran at 946 events a second, against 37,495 without the re-sends. The two now run within a few percent of each other, and a test checks by query plan that every alias lookup in fill and the reads is a seek.

### Changed

- **Amendments name their target by CloudEvent source and id** (PR #177, #171): each store resolves the target when it fills the amendment, so a store replaying another's log applies it the same way. An amendment whose target has not filled waits in `_waiting` and applies when the target does. The store refuses no amendment for its timing and allows one in every class. Amendments of one event stack by known-at and then event id in any arrival order, one known before its target counts from the target's own known-at, and a patch of `data.axis` moves the version to the patched point. Fill now refuses only an amendment that is malformed, leaves the event invalid or targets an event with no hearing of its own, and a refused one reaches `stopped()` at the try limit.
- **A worker reads with its own cursor and saves in a group commit** (PR #174, #173): `next`, `done` and `failed` on the queue now change only memory. The heartbeat, `flush` and `close` save every changed worker in one transaction, including when no event was accepted, and a save that fails is reported as `Failure::Workers` and tried again. After a crash a worker resumes from its last saved cursor and is handed again everything after it, including what it closed since the last group commit, about 20 ms of work at the default interval. A second handle reads a close only once it is saved. `done_keeping(worker, cursor, state)` keeps an opaque string with the cursor, read back with `kept`, and `lag` and `slowest` let a producer apply back-pressure, while `accept` itself never blocks or refuses for lag. A worker's own cost fell from 5.4 ms per event, measured by an app on v0.5.0, to 0.20 µs in a release build, measured once. `Graph::next`, `done` and `failed` stay on the store at one durable write each, and the queue no longer calls them.
- **Fill logs `rannoch.refilled`, so workers see one more type** (PR #194, #151): an event that succeeds on retry now appends a `rannoch.refilled` event, whose data names the retried event's place, in the same transaction, so a relay reads the fact again and tells it as a change. Every worker is handed this event, and one that does not care closes it as done. `rannoch.query`, `rannoch.answer` and `rannoch.report` are also rannoch's own types now. They are logged and fill no table.
- **Full indexes, and the newest known-at kept** (PR #184, #182): no index on rannoch's tables has a `WHERE` clause any more, so fill and the reads no longer prepare their statements again for each bound value. Each fill batch keeps the highest known-at ever filled in `_newest`, and a query with no known-at reads it instead of scanning every fact table, which took `describe` from 26.3 ms to 0.022 ms in the bench. The kept value is a high-water mark: after an amendment makes an earlier one redundant it can exceed what the store's facts hold, and only the answer's `known` differs. A 306,000-event fill went from a median of 12,476 to 36,157 events a second.
- **Every connection takes a 64 MB page cache** (PR #188, #185): the store now sets a 64 MB cache, `temp_store=MEMORY` and `wal_autocheckpoint=10000`, and leaves `synchronous=FULL`, `fullfsync=ON` and `secure_delete=ON` as they were. Each open handle can hold up to 64 MB, so a queue and a second handle for reads are up to 128 MB, and a `copy_to` read-back holds one more while it runs. The same fill went from a median of 34,577 to 57,217 events a second.
- **Fill builds each statement once and runs fewer per event** (PR #189, #186): statement texts are built once per process or per ontology load, and fill keeps each handle for the whole transaction, so no event formats SQL or hashes its text. A link no longer looks up its class ids first, going from 8 statements to 5, and a node's first hearing skips the current-version lookup, going from 7 to 6. `fill_runs_fewer_statements_per_node_and_link` fails if either count rises. The same fill went from a median of 57,117 to 90,455 events a second, and a `.dump` of one log filled by both builds was byte-identical. The release check on main measured 88,294-91,381.
- **Tests count what the code does, not how long it takes** (PR #195, #192): the wall-clock bounds in the queue, store and probe tests are gone. `AGENTS.md` now states the rule, and the only clock left in a test is a guard that fails a hung test. The worker's cost is checked by counting trips to the store: `next` once a chunk and `done` never. The figures in `docs/inbox.md` are stated as measured once, not enforced.

### Removed

- **The history key and the single point** (PR #177, #171): `At`, `HistoryKey`, `Class::history`, `Graph::link_known_at` (use `link_state_at` with a `View`), `Version` and `Hearing`'s `point` and `integer`, `End::Ended`'s `at`, `NodeFact`'s `time` and `integer`, and `LinkFact`'s `time` are gone. So are the amendment by log id in `subject` and the refusals of an amendment for its timing or an integer-keyed class. `NodeRef` moved to `rannoch-ontology` and is still re-exported from `rannoch-cloudevents`.

### Known issues

- **Finding an amendment's target scans the log** (PR #177, #171): one amendment's fill took about 23 ms on a 22,619-event store. Events that are not amendments do not pay for this while a store has no renames and no amendment waits.
- **`relation:<name>` tables still hold corrected links** (PR #191, #190): an app's own SQL over those tables sees a link found wrong, which the reads do not list.
- **Listings are whole and filters are simple** (PR #179, #175): `links` and `nodes` have no paging, filters are equality only and ANDed, and an index can be declared only with its class.
- **A relay's fold and walk time swings for a reason not found** (PR #194, #151): over the 902-node relay it reported a p50 of 1.49-1.75 ms and a p99 of 2.49-3.09 ms, and it moves between about 0.5 and 1.8 ms from run to run. An importer's in-process read of 216 links through the graph, predicted at under 2 ms and read once a run, took 2.28, 0.91 and 2.43 ms, and its swing is unexplained too.
- **`reread` takes as long as the log** (PR #194, #151): it replays the log up to the report's cursor into a temporary graph, which took 1.4-2.0 s over 54,000 events in an earlier toy run.
- **No public lookup from a CloudEvent id to a log id** (#164): amending no longer needs one, since an amendment names its target by source and id. A lookup is still planned, for tracing an event a mistake came from.
- **Carried from 0.5.0**: delivery is at least once with no dedupe by CloudEvent id, so workers must be idempotent (PR #144, #142). A copy is not durable on return (#154). The queue owns its graph and takes the ontology once, so reads go through a second handle and later declarations need the queue reopened (PR #163, #162).

## 0.5.0

Minor release: the second edition replaces the first, which while rannoch is 0.x makes this a minor release, though nothing of the old public surface survives. The root `rannoch` crate is gone and the root `Cargo.toml` is now a virtual workspace whose `[workspace.package]` version is the version of record. An app depends on `rannoch-store`, and on `rannoch-queue` for the inbox, pinned at the tag: `rannoch-store = { git = "https://github.com/runlegion/rannoch", tag = "v0.5.0" }`. Every write is now a CloudEvents 1.0 body. There is no migration from a store written by the first edition. The first edition stays at the tag `v0.4.0.a` for anyone still on it.

The second edition is one app's graph store in one SQLite file, fed through an inbox. The app accepts CloudEvents into a queue that commits them every 20 ms. Fill folds each committed event into the history tables, and every one of the app's workers is handed every committed event, in log order, through `next`, `done` and `failed`. Facts keep the first edition's history model: a keyed content identity, a point on the class's axis, a valid time, endings and corrections. They also gain a known window, so an amendment corrects an event without changing it, and a read as known before the amendment still returns what was written. Four crates are built: `rannoch-store`, `rannoch-queue`, `rannoch-cloudevents` and `rannoch-ontology`, beside the unchanged `rannoch-probe`. In crash tests that killed the process every 50-300 ms, through 300,000 events and through a run of amendments, no event was lost, doubled or left unfilled. Worker files (`rannoch-worker`), the harness that runs them (`rannoch-harness`) and the steps they use (`rannoch-processor` and the eleven `rannoch-processor-*` crates) are workspace members but empty scaffolds that do nothing yet. They are a design, written up in `docs/flows.md` for review before they are built. Until then an app writes its workers in its own code.

### Added

- **`rannoch-store`, the graph file fed by CloudEvents** (PR #140): `rannoch_store::open(path, &key)` opens or starts a store under the app's 32-byte key. The store holds only a check value of the key, and opening under another key returns `Error::KeyDiffers`. `Graph::declare` records a class or relation, each as its own event. `Graph::commit` appends CloudEvents bodies to the log, each with a place (`Cursor`) that is never reused and a fresh `UUIDv7` log id. It refuses an id that is not `<uuidv7>:<fact>` and a node of a time- or integer-keyed class that is missing its key. `Graph::fill` then folds the log into `_hearings`, `_aliases`, `_ends`, `_endings` and `_seen`, and into one `class:<name>` and `relation:<name>` table per declared class and relation for the app's own SQL. In a relation table both ends are foreign keys, so a link between the wrong classes cannot exist there. The event types are `rannoch.node.<class>`, `rannoch.link.<relation>`, `rannoch.ended.<relation>`, `rannoch.corrected.<relation>`, `rannoch.amended` and `rannoch.declared.<name>`. Any other type is the app's own: it is logged and handed to workers but filled into no table. The reads are `find`, `find_as_of(class, key, date, known_at)`, `state_at`, `link_state_at`, `link_known_at`, `hearings`, `link_hearings`, `seen`, `link_seen` and `link_end`, ported from the first edition's single-line history. A link that names a node not yet heard waits in `_open`. When the node arrives, fill closes the link and appends a `rannoch.closed.<relation>` event for workers. Every commit is durable: the file runs in WAL mode with `synchronous=FULL` and `fullfsync=ON`.
- **`rannoch-ontology` and `rannoch-cloudevents`, the pure halves of the store** (PR #140; PR #143, #141): `rannoch-ontology` holds classes, relations, properties, value types and history keys, with the checks of a declaration against what is declared (`Ontology::check`), a link's ends against its relation (`Relation::holds`) and values against their types (`Class::check`), and no I/O. `rannoch-cloudevents` reads a CloudEvents 1.0 body into the fact it states (a node, a link, an ending, a correction, a declaration, or none), reads an event's attributes without its data, and owns `EventId`, `Date`, `ValidTime` and `NodeRef`. `EventId` keeps its field private and parses through `FromStr`. `rannoch-store` reads every event through it and re-exports these types, so most apps depend on the store alone.
- **`rannoch-queue`, the inbox** (PR #144, #142): `Queue::open(graph, Queue::INTERVAL)` takes the `Graph` by value and starts a heartbeat. First it fills whatever the log holds past the tables, which a process killed between a commit and its fill leaves behind. In a crash test that left 205,906 of 300,000 events logged but not filled until this was done. `accept` and `accept_from(body, producer, position)` check a body against the ontology the queue took when it opened. They refuse a bad body at once with its reason, and otherwise hold it in memory and return a `Ticket`. Every heartbeat (or `flush`, `close` or drop) commits what is held in one transaction with a savepoint per event, then runs fill, moves the committed watermark and only then tells `subscribe` subscribers. It releases the graph before telling them, so a subscriber may call back into the queue. A producer's position commits with its events, and after one of its events fails its later events in the batch are not committed, so `position(producer)` is where it resumes without loss or doubling. Failures travel as `Failure`, through `flush`, `close`, `take_failures` or `on_failure`. Declarations go through `Graph::declare`, never `accept`.
- **Workers in the app's own code** (PR #144, #142; PR #146, #145): a worker is a name with a place in `_places`. `next(worker)` hands it the next committed event and marks it in progress, `done` closes it, and `failed` keeps it with its reason. Every worker sees every committed event in log order, independent of the others. On a new run, `next` first hands back the oldest event an earlier run left in progress, so a worker killed mid-event picks the event up again: one killed 34 times drained 3,001 events with every one done. `state` reports one event's state for a worker, and `remove_worker` deletes a worker's place and rows.
- **The processed mark** (PR #152, #149): `processed()` is the lowest point every worker has finished. A failed event counts as finished. Fill is a worker, so the mark never passes what fill has not reached, and it never passes the committed watermark. It replaces the first edition's registered followers and deletes nothing.
- **Amend and rename** (PR #158, #147): an amendment is a `rannoch.amended` event whose subject is the log id of the event it corrects and whose data is a JSON Merge Patch (RFC 7386) of that event. Fill re-derives the target's hearings with every amendment applied in point order. Each hearing that now reads differently becomes a new hearing known from the amendment's point, and the hearing before it closes at that point. The amended event in the log never changes. A patch to the subject is a rename: fill maps the old key to the new one in `_renames`, hears the node's events and every link to or from it again on the new key, and copies link endings and corrections across. Later events naming the old key land on the new key, and `find` returns `None` for a key renamed away. An amendment is refused, as a failed try that never stops fill, when its target made no hearing of its own, belongs to an integer-keyed class, or does not exist. It is also refused when its point is before the target's record time, the target's own point or the latest amendment already applied, or when its patch leaves the event invalid. Amendment is meant for mistakes, and change is recorded as new events.
- **Fill retries and stops at a try limit** (PR #157, #156): fill runs as the reserved inbox worker `rannoch.fill` (`FILL`). An event it cannot fill rolls back alone, is closed as failed with its reason and one more try, and fill carries on. Later fills try it again, each event at most once per fill, until the try limit: 3 unless set with `set_try_limit`. `stopped()` lists the events past the limit with their last reasons, and `retry(cursor)` resets one. An event that succeeds on retry reads as if it had filled the first time. A fault outside any one event's fill ends that fill, keeping the batches already committed, and the queue reports it as `Failure::Fill`.
- **Fill commits in growing batches** (PR #161, #159, #160): each batch takes its own write transaction, reads fill's place inside it, and commits its events with fill's new place. The first batch's budget is 25 ms (`FILL_BUDGET`), and each next one runs four times longer, up to 1 s (`FILL_BUDGET_MAX`). This way a process killed often still keeps its progress, and a long fill commits only a few times. The budget is checked after every event, so each batch commits at least one. A batch runs under one savepoint and falls back to one event at a time only when an event in it fails. While the store holds no rename, fill does no rename lookups.
- **`copy_to`, a copy of the store at a committed point** (PR #155, #150): `Graph::copy_to(path)` writes the store into a new file with SQLite's `VACUUM INTO` in one read transaction and returns the cursor the copy holds. It takes no write lock and records nothing in the store. It refuses a path that exists and removes its file if the copy fails.
- **Documentation for the second edition** (PR #163, #162; PR #168, #166): `README.md` says what is built and what is designed. `docs/store.md` and `docs/inbox.md` walk through the store and the inbox, following two runnable examples (`cargo run -p rannoch-store --example store`, `cargo run -p rannoch-queue --example worker`). `docs/flows.md` is the design for worker files, open for review. `docs/architecture.md` describes how the second edition is built, labels every part built or designed, not built, and lists its limits.

### Changed

- **The workspace is the release unit** (PR #167, #165): `release.toml` reads the version from `workspace.package.version`, and the release workflow refuses a tag that does not name it. CI tests the whole workspace with no exclusions. The probe's dedicated platform runs and its 512 MiB cgroup test are no longer separate CI steps.

### Removed

- **The first edition** (PR #167, #165): the root `rannoch` package and its tests are gone from main and kept at the tag `v0.4.0.a`. With it go `Graph::write`, `Write`, `Unit` and `Ending`, since writes are now CloudEvents. Also gone are `walk_as_of`, `Count`, `describe`, `replace` (renaming by amendment covers changing a node's key) and `derived` with `derived_from`. Followers (`register`, `advance`, `unregister`) are replaced by worker places and the processed mark. Purging (`Graph::purge`, `Purge`) is designed as #148, and snapshots (`Graph::snapshot`, `Snapshot::rebuild`) give way to `copy_to` and a snapshot tool designed in #154. The 0.3.0 known issue that a snapshot costs about the store's size (#111) no longer applies.

### Known issues

- **No lookup from a CloudEvent id to a log id** (#164): an app that will amend an event keeps its log id from `commit`'s result, from `events().since(...)` or from the `Event` a worker takes. A queue app gets a `Ticket` from `accept`, not an `Event`, so only the last two are open to it. A lookup is planned, for tracing an event a mistake came from.
- **Delivery is at least once, with no dedupe by CloudEvent id** (PR #144, #142): the log mints a fresh log id for every event, and the queue accepts a body it has accepted before. A repeat under the same CloudEvent id records nothing in the graph, but every worker is handed both events, so workers must be idempotent.
- **A copy is not durable on return** (#154): `copy_to` does not flush the copy to the device. A durable snapshot tool built on it is designed, not built.
- **The queue owns its graph and takes the ontology once** (PR #163, #162): an app with a queue open reads, and calls `stopped`, `retry`, `set_try_limit` and `copy_to`, through a second handle from `rannoch_store::open`. Declarations made after `Queue::open` are not seen until the queue is closed and opened again.

## 0.4.0

Minor release: two public signatures change, which while rannoch is 0.x makes this a minor release. `Graph::end_link` returns `Ending { event, live_from }` instead of `Event`, and `LinkFact` gains `time`. No schema migration: a link stored without a time keeps its old content identity, so a store written by 0.3.0 opens as it was. The tag is still the release: pin `rannoch = { git = "https://github.com/runlegion/rannoch", tag = "v0.4.0" }`.

An app can now write its existing history through the ordinary write API, and every link and every ending keeps its real time (FR-RANNOCH-085). Until now a link written in a unit of a time-keyed class was heard at the store's record time, so an ending at its real, earlier time sat before the link's own hearing and silently reopened the link.

### Added

- **A link takes its unit's time** (PR #135, #134, FR-RANNOCH-085): for a unit of a `HistoryKey::Time` class, the write path passes the unit's time to its links in `LinkFact::time`, and the time travels in the `Wrote` event, so a rebuild and any arrival order place the link at the same point. The time joins the link's content identity only when one was supplied. Links of origin- and integer-keyed classes are unchanged. An ending at its own earlier time now compares against the link's real point, so history written long after it happened keeps its endings.
- **An ending says when a later hearing keeps the link live** (PR #135, #134): `Graph::end_link` returns `Ending { event, live_from }`. When the ending lies before a later live hearing the link still reads as live, and `live_from` is the point of that hearing, read from `link_seen`; otherwise it is `None`.

### Changed

- **A link's newest version follows its unit's point** (PR #135, #134): a link written in a time-keyed unit is now ordered at that unit's time rather than the record time, so links arriving after newer ones are really ordered by the time they carry. Callers that used `end_link`'s returned `Event` read `ending.event`.

## 0.3.0

Minor release: the public signatures change again, which while rannoch is 0.x makes this a minor release. `rannoch::open`, `rannoch::rebuild` and `Snapshot::rebuild` take a 32-byte history key (`Option<&[u8; 32]>`, and `None` is refused), `HistoryKey::Recorded` is renamed `HistoryKey::Origin`, `find_as_of` and `walk_as_of` take a `known_at: Option<At>` and `Count` gains the same field, `Graph::forget` is replaced by `Graph::purge`, `Graph::end_link` takes a `ValidTime`, `Graph::derived` returns `FactRef`, `LinkFact` gains `derived_from`, and two writes that used to land are now refused: a link from a source never heard, and a write to a time- or integer-keyed class missing its key. A store written by 0.2.0 (kept as `tests/fixtures/store-0.2.0.rannoch`) opens whole, but its schema is migrated in place at open. At open, `_derived` is re-keyed by (class, key, to_key), `_events` gains an indexed `id` column, replacement fates gain their point and event id, aliases gain a point, and a store that already held a graph is recorded as not yet clean of pre-`secure_delete` leftovers. The first time it is opened under a key, the log is heard into the new history tables (`_hearings`, `_aliases`, `_ends`, `_endings`, `_seen`) and a standing rule is kept in `_purge_rules` for each earlier forget or purge.

This is the history part of the 0.2 redesign (FR-RANNOCH-048, 062, 064, 065, 066, 068, 069, 071, 072, 076, 078, 079, 082 and 084). Every write is now a hearing of a node or link at a point on its class's history axis, with a keyed BLAKE3 content identity, so an identical hearing adds nothing and a return to earlier content is a new occurrence. Current state is the newest version on the axis rather than the last to arrive, past versions are readable at a point or as of a valid time, and the same events in any arrival order give the same answers. A link can end at its own time or be found wrong. A purge leaves nothing of what it purged, in the store or its snapshots, and stands as a rule against what arrives after it. One dependency was added: `blake3`. The tag is still the release: pin `rannoch = { git = "https://github.com/runlegion/rannoch", tag = "v0.3.0" }`.

### Added

- **Every write is a hearing at a point, with a content identity** (PR #91, #82): a hearing's content and source are hashed with BLAKE3 in keyed mode under the 32-byte key the app passes to `open` and `rebuild`. The store holds only a check value of the key, never the key. A local write identical to a hearing already held writes no event and returns the event that names that hearing. An identical event arriving under its own id from another store is held as an alias, and the smaller id names the hearing. `Unit::at` and `Unit::integer` carry the time or integer a class's history is ordered by, and a write missing that key is refused. A class with no declared key (`HistoryKey::Origin`, formerly `Recorded`, still decoded under its old name) is ordered by the millisecond in its event's UUIDv7 id, the time the first store recorded it.
- **Current state is the newest version on the class's axis, and state at a point is readable** (PR #99, #72): every hearing is a version row, and `find` reads the newest by point (or, for an integer-keyed class, by integer and then point), with ties going to the larger event id. A late older write is kept as a version and changes nothing current. New public items are `At`, `Version`, `Seen`, `Graph::state_at`, `Graph::link_state_at` and `Graph::seen`. This fixes 0.2.0's known issue that `find` returned the last-arrived version.
- **A link ends at its own time; a link found wrong is a correction** (PR #98, #92; PR #102, #101): `Graph::end_link(relation, from, to, at, valid, source)` appends a `Change::Ended` carrying the ending's point and the valid time the link stopped holding, and `Graph::correct_link` appends a `Change::Corrected` with no point. `Graph::link_end` reads either back as `End::Ended` or `End::Corrected`. Ending a link leaves its hearings in place, and ending or correcting a link never heard is refused. A live hearing at a later point than an ending reopens the link.
- **Reads as of a valid time return the version that held then** (PR #103, #83, FR-RANNOCH-048): `find_as_of`, `walk_as_of` and `Count { as_of, .. }` take, for every node and link they touch, the greatest version valid on or before the date, and with `known_at` only versions heard by that point on the class's axis. A version or link ending whose valid time is unknown is never read as now: the version is not returned, and a walk or count that would follow a link with an unknown ending valid time is refused, naming the link. A grouped count as of a date groups by the property's value then. This replaces 0.2.0's refusal for `find_as_of` when a past version might hold.
- **First heard, last heard and when a link ended in one read** (PR #110, #87): `Graph::seen` and the new `Graph::link_seen` return first heard and last heard on the axis, first recorded in this store, first true, the count of facts (`Seen::count`) and the ending (`Seen::ended`) from one `_seen` row kept in the same transaction as each hearing. A node or link with one fact keeps no row. A store written before `_seen` is backfilled once at open, and a backfill that fails leaves the store as it was and runs again on the next open (PR #113).
- **The history walk goes back to first heard** (PR #125, #86, FR-RANNOCH-069): `Graph::hearings` and `Graph::link_hearings` return every hearing on the class's declared axis, back to first heard, across aliases and snapshots. An integer-keyed class used to walk in arrival-time order.
- **The same events in any arrival order give the same answers** (PR #119, #89, FR-RANNOCH-084): on replay a link that arrives before its end nodes waits open and closes when they arrive, a `Closed` event arriving before its open row changes nothing, a node's replacement fate is the greatest by point and then event id, and a link's state at a point is the newest of its live hearings and endings. Only first recorded still depends on arrival.
- **A purge leaves nothing of what it purged** (PR #117, #85, FR-RANNOCH-071): `Graph::purge(target, rule, source)` replaces `Graph::forget`. `Purge` names a fact by its identity, a write source's stream, a node with every part of it and their links, or a link, one source's word about a node or link, or one source's word everywhere. It removes the match from the store and every snapshot the store recorded, leaving no event body, hearing row, content identity or orphaned event id, in one IMMEDIATE transaction under `secure_delete`, then truncates the write-ahead log. The purge event records its rule and kind plainly and each target only as a keyed match value. `Change::Forgot` in an old log still decodes and replays.
- **A purge stands as a rule against what arrives after it** (PR #128, #88, FR-RANNOCH-072): the rule is kept in `_purge_rules` in the purge's transaction, and a matching hearing, ending or correction arriving later, on the write path or on replay, is never stored. A rebuild from events or a snapshot holds the same rules, and a snapshot purged by a later purge keeps one rule row per rule. Stores that purged before rules were kept and legacy forgets stand rules too. A follower sees a purge only as its rule event, never what was purged (PR #130, #107, FR-RANNOCH-078).
- **Replacing a node carries its history to the new key** (PR #121, #105): `Graph::replace` and its replay move the old node's hearings, `_derived` rows and every link it ends, with the links' hearings and endings, to the new key. A moved link that lands on one already held merges into it. The old node keeps its row and fate, and `find` and `describe` answer it with its class, key and fate and no properties.
- **Links name the events they were derived from** (PR #126, #73): `LinkFact` gains `derived_from`, a write's derived-from ids apply to its links as well as its nodes, and `Graph::derived` returns `FactRef` for both. Checking that a named event exists is an index lookup on a new `_events.id` column (filled at open for older stores) instead of a scan over log bodies.
- **A snapshot keeps every version and every event id** (PR #112, #84, FR-RANNOCH-062; PR #116, #96): a snapshot replays every event up to its cursor into the new file under each event's own id and place, and copies the aliases its hearings hold. It used to keep only forget events, which lost every other event id. It still never takes the graph's write lock, and fills its file under a rollback journal before switching to WAL so commits sharing the disk are not slowed. An identical rewrite on a graph rebuilt from a snapshot returns the hearing held and writes no event.

### Fixed

- **A rebuilt graph's watermark no longer sits below its snapshot's cursor** (PR #120, #78, FR-RANNOCH-064, FR-RANNOCH-079): `Events::committed` now reads the log's high-water mark, which never moves back on delete, and a snapshot raises its file's mark to at least its cursor. This fixes 0.2.0's known issue where `advance` refused cursors a rebuilt graph already held.
- **A return to earlier content is a new occurrence** (PR #118, #93): a source writing v1, v2 and then v1 again left the node reading v2, because the third write matched the first hearing's identity. Aliases now carry a point (existing aliases get their id's millisecond at open), a match that is not the current version is recorded as an occurrence at its own point, and every version pick chooses among occurrences. A return applies only where rannoch assigns the point (`HistoryKey::Origin`): where the writer supplies it through `Unit::at` or `Unit::integer`, the point is part of the identity, so an identical hearing stays held with no event however old. The ending check's last live hearing also picks among occurrences, so a link that ended and is then heard again as before reads live after that occurrence.
- **An arrived event that adds only an alias is kept in the log** (PR #122, #94): a rebuild used to hold such an arrival in state without writing it to the log, so a graph rebuilt from that log lost the alias. Every arrival is now stored under its own id and place.
- **An event whose id is not a UUIDv7 is refused** (PR #123, #97): a foreign event reaching `rebuild`, `Snapshot::rebuild` or the first-key backfill was placed at the epoch in silence. It is now refused with `Error::Refused`, and nothing of it is written.
- **A purge drops a removed id from other facts' derived-from lists** (PR #129, #127): the purged id stayed in the `derived_from` list in the log body of every fact that named it. A purge now finds those bodies by the id itself and drops it, in the store and its snapshots.
- **No old copy of a purged body survives in free space** (PR #126, #73; PR #131, #124): every connection now opens with `secure_delete` on, since a page split made before a purge could leave an old copy of a cell behind. A store that already held a graph before this build is vacuumed once, after its first purge, and recorded clean, so later purges do not vacuum.

### Changed

- **Forgetting is replaced by purging** (PR #117, #85): `Graph::forget`, which kept a forgotten node's class and key in the log, is gone along with FR-RANNOCH-042. Use `Graph::purge` with `Purge::Entity`. A `Change::Forgot` in an existing log still decodes and replays, and stands a purge rule.
- **A link from a source never heard is refused on the write path** (PR #114, #106, FR-RANNOCH-068): such a link used to open and wait on its source. It is now refused, naming the missing key. A target not yet heard still opens the link, and replay, sync and rebuild still accept a link that arrives before its ends.
- **Event ids minted by one process order as minted** (PR #115, #95, FR-RANNOCH-076): hearings tied on point within a millisecond are ordered by event id. `EventId::now` relies on `Uuid::now_v7`'s in-millisecond counter, now documented and pinned by a test.
- **History's ordering and ending checks have one path each** (PR #109, #104): every version pick uses one order, every ending check one function and replay one hearing path. No behaviour change.

### Known issues

- **A snapshot costs about the store's size** (#111): because a snapshot replays every event up to its cursor, it writes a file about the store's size (0.95x in raid-feed 2's 16x run) and competes with commits for CPU and disk while it runs. Copying version rows directly is planned.

## 0.2.0

Minor release: the public signatures change, which while rannoch is 0.x makes this a minor release. Property values are typed (`Value` replaces `String` in `Node`, `NodeFact`, `Description` and `Unit::new`), `Class::properties` maps each property to its `ValueType`, `Declaration::Property` carries its type, `Node` and `NodeFact` gain `derived_from`, and `Graph::compact` is removed in favour of `Graph::snapshot`. A store written by 0.1.1 opens whole with no migration step: rannoch's new tables (`_derived`, `_followers`) are created on open, its properties read as text and its classes keep recording order.

This is the first part of the 0.2 redesign (FR-RANNOCH-055, 056, 057, 058, 061, 062, 063, 064, 075, 079, 080 and 081). An app can now write through an in-memory queue that a heartbeat commits as one transaction with a savepoint per write; `Graph::write` still commits directly. A write that breaks its class's declaration is refused when it is written, and one that fails at commit is reported with every write that depended on it. The store keeps every event: a snapshot replaces compaction. Followers read events since a stored cursor, bounded and filtered, from this process or another, and the graph reports the mark every registered follower has read. A fact can name the events it was derived from. A new workspace crate, `rannoch-probe`, measures the memory a host allows and how fast a directory takes durable writes. The tag is still the release: pin `rannoch = { git = "https://github.com/runlegion/rannoch", tag = "v0.2.0" }`.

### Added

- **Declared value types and a class's history key** (PR #56, #47, FR-RANNOCH-055): a class declares each property's `ValueType` (`Text`, `Integer`, `Decimal`, `Float` or `FloatVector(n)`) and its `HistoryKey`: `Integer` or `Time` supplied by the writer, or `Recorded`, the default. Values sit in typed columns and read back as `Value` of their declared type. An integer such as 9007199254740993 stays exact, and a decimal is held as text and keeps every digit. `Ontology` names each class's history key. A store written by 0.1.1 (kept as `tests/fixtures/store-0.1.1.rannoch`) opens with every event, its properties as text and its classes in recording order.
- **A write that breaks its class's declaration is refused at once** (PR #57, #48, FR-RANNOCH-056): the property checks moved from each piece into the whole-write check. A wrongly typed value is refused before any piece commits, and a node missing a property its class declares is now refused too.
- **The heartbeat write queue** (PR #65, #49, FR-RANNOCH-057): `Queue::open(graph, interval)` takes a `Graph` and commits on a heartbeat (`Queue::INTERVAL` is 20 ms). `Queue::write` checks the write against the in-memory ontology, refuses at once what it refuses, and otherwise returns a `Ticket` before the write is committed. A heartbeat commits everything queued, advances the committed watermark (`Queue::committed`) and only then fires the `Queue::subscribe` subscribers, so a subscriber never hears of an event that is not committed. `Queue::flush` commits now and returns when every write accepted before it is committed.
- **A heartbeat's batch is one transaction with a savepoint per write** (PR #70, #62, FR-RANNOCH-058): each write in the batch runs unsplit under its own savepoint, so one failing write rolls back alone and the rest commit. A batch of more than 1,000 changes lands whole for a reader, never in part. A link from a node that a failed write would have brought new fails with it, while a link from a node already in the graph keeps its source. If the file rolls back the whole transaction, every ticket in the batch fails rather than continuing in a second transaction.
- **Dropping or closing the queue commits what it holds** (PR #69, #61, FR-RANNOCH-061): dropping a `Queue` stops the heartbeat and commits what is still queued, so a process that returns or panics with unwinding loses no write. `Queue::close` does the same explicitly for a process about to exit without unwinding.
- **A write that fails at commit is reported, never dropped in silence** (PR #77, #63, FR-RANNOCH-075): every queue failure travels one channel, the public `Failure` (`Write`, `Heartbeat`, `Subscriber` or `Unfired`). Each is reported once, to whichever takes it first: `flush` and `close` return it, `take_failures` collects it, or the `on_failure` handler receives it when the queue drops. A failed write comes back with every write that depended on it, such as a link from a failed node. A subscriber that panics does not stop the heartbeat. If the heartbeat itself panics mid-batch, the batch goes back to the front of the queue in order and the next flush, close or drop commits it or reports each write.
- **Snapshots replace compaction; the store keeps every event** (PR #60, #50, FR-RANNOCH-062): `Graph::snapshot(cursor, path)` writes the graph's state and ontology at a cursor into a file of its own. It reads the log, deletes nothing and never takes the graph's write lock. `Snapshot::rebuild(later, path)` starts a graph from the snapshot plus the events after its cursor, keeping declarations, the history key, declared types and each node's fate (forgotten or replaced). A new reader starts at `events().since(snapshot.cursor())`. The forgotten-fate defect carried in 0.1.1's known issues (#30) no longer applies, because nothing erases events.
- **Events since a stored cursor, bounded and filtered** (PR #68, #51, FR-RANNOCH-063): `Events::since_until(cursor, until, keep)` returns the events after a cursor up to an inclusive bound, keeping only the changes `keep` accepts. `Cursor` serializes as its number so an app can store it. A rebuild, from the start or from a snapshot, replays each event under its own place in the log, so a stored cursor names the same event afterwards and a follower behind a snapshot still catches up.
- **The committed watermark is readable across processes** (PR #74, #52, FR-RANNOCH-064): `Events::committed` returns the cursor of the last committed event. Another process on the same file follows commits by reading it and taking `since_until` its own cursor up to it, so it sees each committed event once and nothing uncommitted.
- **Registered followers and the processed mark** (PR #76, #58, FR-RANNOCH-079): `Events::register`, `advance`, `unregister` and `followers` keep named follower cursors in `_followers`, and `Events::processed` reports the lowest of them, the point every registered follower has read. A new follower holds the mark at the start until it stores a cursor, and unregistering releases it. Advancing past the committed watermark is refused, so the mark never covers an event that has not arrived. A snapshot carries registrations, and `Snapshot::rebuild` lowers any carried cursor past the rebuilt graph's watermark to it. The mark deletes nothing.
- **A fact names the events it was derived from** (PR #75, #59, FR-RANNOCH-080): `Write::derived_from(events)` names the events a write's nodes were derived from, and each node reads back with `derived_from` naming them. `Graph::derived(event)` answers the nodes derived from an event. A source event the graph does not hold is refused at once. Sources survive a snapshot rebuild, an identical rewrite naming new sources records them, and forgetting a node removes its derived-from rows.
- **`rannoch-probe`** (PR #66, #64, FR-RANNOCH-081): the repository is now a Cargo workspace with a second crate. `rannoch_probe::memory(cap)` reports a host's total memory and the memory it allows, the least of the total, the limit set by the process's cgroup or any ancestor cgroup, and the caller's cap. `rannoch_probe::disk(directory, budget)` measures a directory's durable write rate (`File::sync_all`, `F_FULLFSYNC` on macOS) and the time of one flush within a time budget. When it overruns, `Error::Budget` carries the flush in progress and the overrun. A measurement records the OS and when it was taken, and the probe stores nothing. CI runs its tests on Linux, macOS and Windows, and on Linux once more under a 512 MiB systemd scope.

### Fixed

- **Typed values: non-finite floats, grouped counts and later declarations** (PR #67, #55): a write carrying NaN or an infinity in a float or float-vector property is now refused when it is written, so every accepted event reads back and replays. A count grouped by a non-text property reads the group from its stored value instead of failing. A property declaration carries its value type (text when an older event names none), and redeclaring a property with another type is refused. A rebuild or snapshot replaying a node with a property its class does not declare fails, naming the event, instead of dropping the property.
- **`find_as_of` refuses rather than answers wrong** (PR #79, #71): `find_as_of` reads only a node's current version, so when that version was valid after the asked date it answered `None`, even if an earlier version held then. It now returns `Error::Refused` ("past versions are not readable yet") when the current version is valid after the date or has an unknown valid time and the node had an earlier version. A node with only one version answers as before, and the function's documentation states what it can and cannot answer.

### Changed

- **Compaction is removed** (PR #60, #50): `Graph::compact`, which deleted events, is gone along with FR-RANNOCH-043. Use `Graph::snapshot` and `Snapshot::rebuild`.
- **CI runs on merge groups and across the workspace** (PR #54, #53; PR #66, #64): the merge queue tests what it merges, and fmt, clippy, tests and doc tests cover every workspace crate, as does release preflight.

### Known issues

- **`find` returns the last-arrived version** (#72): `Graph::find` returns the version of a node that arrived last, not the newest on its class's declared history key. A write for an earlier point that arrives after a later one overwrites the current state, so two graphs holding the same events in different arrival orders can disagree on what is current. Finding the newest version on the declared axis ships in 0.2.1. Until then, a class with no declared history key behaves as documented (recording order).
- **A rebuilt graph's watermark can sit below its snapshot's cursor** (#78): after `Snapshot::rebuild` with few or no later events, `Events::committed` can report less than the snapshot's cursor, so `advance` refuses cursors the rebuilt graph already holds and carried followers re-read events. Nothing is lost. The fix ships in 0.2.1 with the history work.

## 0.1.1 (2026-10-18)

Patch release: the first tagged release of rannoch, numbered 0.1.1 so that 0.2 stays the name of the planned redesign (the 0.2 spec, FR-RANNOCH-056/062/071); nothing depended on rannoch before this tag, so the changed `walk` signature (#35) breaks no released consumer.

rannoch is one graph for the Rust projects in this ecosystem. Every change to a graph is an event. The SQLite tables are state built from those events. The graph presents itself as an ontology, so no read or refusal names a table or column. An app opens a graph file, declares its classes, relations and properties on the graph's own event stream, writes whole units, and reads by find, capped walk, exact count or describe. It can also follow its events from a cursor, compact them, forget or replace nodes, resolve references into other graph files, and rebuild a file from its events alone. Releases are git tags: the crate keeps `publish = false` and is not on crates.io, so consumers pin the tag, as in `rannoch = { git = "https://github.com/runlegion/rannoch", tag = "v0.1.1" }`.

### Added

- **The core: open, declare, write, events, find, walk and count** (PR #15, #2, #3): `rannoch::open` presents a graph file and the ontology its own stream declared. `Graph::declare` writes one event per class, relation or property and builds its table in the same transaction. An identical declaration does nothing, and a conflicting one is refused in ontology terms. `Graph::write` commits a whole `Write` in pieces of 1,000 changes. Each piece is one transaction, and its events land only if the piece lands. If a piece fails, `WriteError` returns the events of the pieces that landed before it. A link to a key that is not present yet waits as an open link and closes with one event when the key arrives. Reads are `events().since(cursor)`, `find`, `find_as_of`, `find_link`, `walk` (capped, in either direction with `<-`) and `count` (distinct, total and grouped tallies over many roots in one query, with an optional relation filter). Storage is bundled SQLite with one table per class and one per relation.
- **A link holds only between its relation's declared classes** (PR #18, #4): `Graph::write` checks the whole write before any piece commits. If a link's source key is a node of a class other than the relation's declared source class, the write is refused with `Error::Refused`, nothing lands and no event is written.
- **Forgetting** (PR #19, #5): `Graph::forget(target, rule, source)` removes a node and every link touching it from live state in one transaction. It rewrites each earlier `Wrote` event that carried the node so the node keeps its class and key but loses its properties, and appends a `Change::Forgot` event naming what left.
- **Compaction** (PR #20, #6): `Graph::compact(cursor)` deletes the log's events up to a cursor the app chooses. Graph state lives in the tables, so counts are unchanged, and event sequence numbers are never reused, so `since(cursor)` still returns every later write for an app to fold onto its compacted base.
- **Open-links read** (PR #17, #7): `Graph::open_links` lists every link still waiting for its other end, with both ends and the kind and key it waits on. If a write adds a node of the wrong kind under a waited-on key, the link stays open and the piece's `Wrote` event reports a `WrongKind`.
- **Describe a node** (PR #22, #8): `Graph::describe(&NodeRef)` returns a `Description` with the node's class, key and properties, its relations by name in both directions with counts, and its containment ancestors (`PartOf`), nearest first.
- **Replacing a node** (PR #23, #9): `Graph::replace(class, old, new)` records the old node's fate and appends one `Change::Replaced { class, old, new }` event in a single transaction. After that, `describe` on the old node answers `replaced_by`.
- **References into another graph file** (PR #24, #10): `Graph::mount(name, path)` opens another graph file under a name. `Graph::resolve(mount, &NodeRef)` answers the target's `Fate` (`Live`, `Forgotten { rule }` or `Replaced { by }`) from that file's own facts only, and writes nothing to the referring file.
- **As-of reads over valid time** (PR #16, #11): `Graph::walk_as_of` and `Count`'s `as_of` read only nodes and links valid on or before a date, checking every link and node along the path. A stated-unknown valid time is never read as now. A read without `as_of` returns unknowns marked `ValidTime::Unknown`.
- **Rebuild from events** (PR #21, #12): `rannoch::rebuild(events, empty_path)` replays a graph's events in log order into an empty file in one transaction, keeping each event's original id. The ontology, nodes, links and open links all come back, and closed links come back with the source they were opened with.
- **Measurement harness** (PR #25, PR #41, #13, #40): `tests/measure.rs` holds `#[ignore]` tests that run NFR-RANNOCH-011, 012, 013, 014 and 016 as written. Each prints the measured value, the target and whether it met the target. They run by hand at verify time, never from a daemon. Since PR #41 they run on Linux (`VmHWM`), macOS (`ru_maxrss`) and Windows (an in-process working-set sample every millisecond) and find legion's store in the platform data directory or `LEGION_DATA_DIR`. A new CI job lints all targets on ubuntu, macOS and Windows in parallel.
- **Release tooling** (PR #43, #42): `release.toml`, `scripts/release.sh`, `scripts/sync-version.sh`, `scripts/test-release.sh`, `RELEASING.md` and a `release.yml` workflow. On a `v*` tag, the workflow checks the tag against `Cargo.toml`, builds, and creates the GitHub release with the matching CHANGELOG section as its notes. It has no crates.io step.

### Fixed

- **A walk from an undeclared class is refused in ontology terms** (PR #26, #8): such a walk used to return the storage error `no such table: class:ghost`. It now refuses with `class ghost is not declared`.
- **A forget takes the node's open links with it** (PR #27, #5): forgetting a node used to leave its open links in live state, so `open_links()` still listed the forgotten key and writing the key again closed the leftover link onto it. Those open links are now removed and named in the `Forgot` event, and a rebuild does the same.
- **A walk asked for every hop ends** (PR #28, #2): a walk with `hops = usize::MAX` never returned once it ran out of nodes before its cap. It now stops as soon as there is nothing left to walk from.
- **Out-of-range dates are refused, and valid times compare by value** (PR #36, #34): writes and as-of reads used to accept dates such as month 13, February 29 in a common year or April 31. Every as-of comparison also compared dates as text, so a node valid `2020-01-01` was not found as of `2020-01`. Writes now check every valid date before any piece commits. `find_as_of`, `walk_as_of` and `count` refuse a bad `as_of`, and all three compare dates as (year, month, day), with a month standing for its first day. Stored valid times are not rewritten, and a file holding an old out-of-range date still rebuilds.
- **Replace refuses equal keys and keys that are not nodes** (PR #37, #33): `replace("item", "x", "x")` used to succeed and leave `x` replaced by itself, and replacing between two absent keys also succeeded. Equal keys now return `Error::Refused`, and a missing old or new node returns `Error::NotFound`. In both cases no event is written and no fate changes.
- **A handle's reads use the ontology the file holds now** (PR #38, #32): a handle used to keep the ontology it loaded at `open`, so it refused, and graphs that had mounted the file refused, a class or property another handle declared later. Reads now check the file's schema version and reload the ontology only when it has changed, so a plain data write costs a read one pragma and no reload.

### Changed

- **`walk` and `walk_as_of` return a `Walk`** (PR #39, #35): both now return `Walk { nodes, capped }` instead of `Vec<(NodeRef, ValidTime)>`. `nodes` holds at most `cap` nodes, nearest first. `capped` is true when at least one more node within `hops` (and valid as of the date, for `walk_as_of`) would have come back under a larger cap. Callers no longer need to ask for `cap + 1` to tell whether they hit the cap. This is a breaking change for any caller built against earlier `main`, which now reads `.nodes`.

### Known issues

- Three defects found before this release are not fixed in it and were closed as to be replaced by rannoch's next design: a write refused for an undeclared class or unknown property can land its earlier pieces (#29), compaction erases forgotten fates so `resolve` answers `NotFound` (#30), and `forget` scans every event, so its cost grows with the log (#31).
